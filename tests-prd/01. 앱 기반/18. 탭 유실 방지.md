# 18. 탭 유실 방지

> E2E: `tests/01. 앱 기반/18. 탭 유실 방지/`

탭 닫기·짧은 본문·빈 내용만으로는 삭제 의도가 아니다. 본문을 모두 비운 뒤 개별 탭을 직접 닫는 경우만 19. 빈 탭 직접 닫기의 명시적 삭제 예외를 적용한다. 서버는 개인 작업공간의 기존 탭 ID 누락을 거부하며, 이동은 다른 개인 그룹·보관 기록 또는 저장 완료된 공유 그룹에 원본이 존재할 때만 허용한다. 공유 이동도 대상 DB 저장이 완료되기 전에는 원본을 제거하지 않는다. 서버가 누락 저장을 차단해도 현재 작성 중인 다른 본문을 버리지 않는다.

명시적 제거 또는 저장소 간 이동 직전 원본은 `notepad_removal_backups`에 트랜잭션으로 보관한다. 이 백업은 일반 이력의 최근 100개 제한과 독립적이며 자동 삭제하지 않는다. 운영 데이터의 직접 삭제는 대상별 사용자 승인을 받아야 한다. 기존 내부 삭제 호출은 개인 탭을 보관하고 공유 탭을 숨기며, 보관 탭 복원은 기존 빈 탭을 대체하지 않고 추가한다.

1. 개인 저장에서 빈 탭·2자 탭·닫힌 탭을 누락하면 baseEventId 유무와 관계없이 거부하고 기존 이력을 보존한다.
2. 개인 그룹 간 이동은 탭 ID와 본문을 유지하면서 저장되고 다른 그룹의 탭도 보존한다.
3. 개인 그룹을 공유로 전환하면 서버에 저장된 원본이 확인된 경우 개인 이력에서 해당 그룹을 제외할 수 있다. 전환 직전 수정한 본문은 실제 이동 본문과 대상 저장값을 대조한다.
4. 공유 탭 이동은 대상 저장 실패 시 원본을 유지하고, 대상 개인 이력 저장 완료 후에만 원본 제거를 허용한다.
5. `confirmedDeletion: true`와 대상 ID로 삭제를 확인하여 제거한 공유 탭의 이전 스냅샷은 별도의 삭제 방지 백업에 보관한다.
6. 보관 기록은 확인된 삭제 ID가 없으면 누락 저장을 거부하고, 삭제 시 원본 백업을 보존한다.
